# Incident: Intermittent 500s from Netlify — 2026-09-23 (open)

## Summary

Netlify returns **HTTP 500** for a share of requests to the shirans site: `Error - Request ID: <id>`, in plain text on a black page. It affects **every deploy of this site, including production (`shiran-gilad.com`)**, and every kind of file, including static assets. It does **not** affect other Netlify sites, and Netlify's status page reported no incident.

**The cause is not in this repository.** The failing responses are produced by Netlify's edge before the request reaches the site's files. See [Why it isn't the code](#why-it-isnt-the-code).

**Status:** open, and needs a Netlify support ticket. There is no Netlify CLI or connector on this machine, so the site's configuration couldn't be inspected.

## Why it isn't the code

- **A static SVG fails.** Nothing in the application runs for `/shiran_logo_icon.svg`: no JavaScript, no redirect rule and no proxy match that path.
- **The failing response has no `Cache-Status` header**, while every good response carries `"Netlify Edge"; fwd=miss; …`. The 500 is generated before cache lookup, so it never reaches the deploy's files.
- **Production fails too**, and production runs `main`, whose client code the redesign has not touched.
- **Other Netlify sites are fine**, and the status page showed no incident — so it is specific to this site.

## Related: a deploy-preview build that failed in 35 seconds

A deploy of commit `5a9fb71` failed 35 seconds after it started (23:26:30 → 23:27:05). That is too fast for this build to have got past dependency install. The same commit built cleanly locally with `npm run build:client-for-deploy`, and an empty retrigger commit built and published on Netlify at 23:29. The most likely explanation is the same site-level instability.

## What to do

1. **Open a Netlify support ticket** with the request IDs above.
2. In *Site configuration*, check for installed **extensions or Edge Functions**. One failing intermittently would produce exactly this pattern; temporarily disabling it is a cheap test.
3. Check the site isn't at a **plan limit** (bandwidth or build minutes).
4. Re-measure:

   ```bash
   for i in $(seq 1 20); do curl -s -o /dev/null -w "%{http_code}\n" https://shiran-gilad.com/shiran_logo_icon.svg; done | sort | uniq -c
   ```

## Impact

Visitors to the live site see an error page on somewhere between one request in five and one in three (6 of 20 on production). When the page request itself fails, the contact form can't load — so a lead can be lost.
